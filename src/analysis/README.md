### Однотипные находки склеиваются

Девять отдельных «screenshot вызван N раз» — это одна проблема в девяти местах сессии.
`merge.py` сводит их в одну находку: `episodes[]` хранит каждый эпизод со своими
`stepIds`, метриками и доказательствами, поэтому проверяемость не теряется.

Склеиваем по цели (`repeated_call`, `similar_call`, `retry_loop` — по ключу вызова;
участки расхода — по типу) и по типу, когда находок много (`file_churn`,
`rewrite_loop`, `repeated_instruction` — от четырёх штук). На коротком логе три
отдельные строки полезнее одной общей, поэтому есть порог.

Эффект на настоящих логах: 288 находок → 223 (склейка по цели) → 150 (порог по типу).
Самый большой лог: 200 → 81, при этом ни один эпизод не потерян.

### Полосы значимости, а не одно число

`severityBand` — `высокая | средняя | низкая`, определяется правилами (см. `severity.py`),
а `severity` нужна только для сортировки внутри полосы. Так требует документ архитектуры:
число вроде `confidence=0.93` нельзя выдавать за измеренную вероятность. `severityRules`
показывает человеку, почему находка попала в свою полосу. `informational: true` — находка
справочная (пауза, дорогой участок, сбой API): она ничего не доказывает сама по себе.

### Рекомендации собирает код

Одна рекомендация на тип находки: действие, основание, способ проверки пользы и **готовый
текст файла**. Четыре формата: патч `CLAUDE.md`, правило для разбора, черновик скилла
(`.claude/skills/project-commands/SKILL.md`) и настройка инструментов
(`tools-to-connect.md` со списком того, что установить или подключить, и
`.claude/settings.json` с черновиком `permissions.allow`, собранным из отклонённых вызовов). Каждая привязана к конкретным
находкам через `findingIds` и цитирует лог в `examples` — общих советов не выдаём.
LLM-этап может переписать формулировки, но если он недоступен, рекомендации в отчёте уже есть.

### Доля ошибок с честным знаменателем

Вызов без результата — это `unknown`, а не успех: `errorRate = падения / вызовы с известным
статусом`, при нулевом знаменателе `None`, а не `0`. `unknownStatusCount` показывается рядом.

## Направления

Шесть направлений из кейса (`required: true`) плюс седьмое — «Инструменты и доступы».
По каждому отчёт даёт явный статус: `found`, `clean` или `insufficient_data`, со знаменателем.

## Что считает код

| type | когда срабатывает |
|---|---|
| `repeated_call` | 3+ одинаковых вызова в окне 10 вызовов; severity выше, если между ними ничего не правили и результат тот же |
| `similar_call` | 3+ близких по смыслу команды Bash (Жаккар ≥ 0.7) — перебор вариантов |
| `retry_loop` | один и тот же вызов падал 2+ раза |
| `repeated_error` | одна ошибка в 3+ разных вызовах |
| `high_failure_rate` | доля падений ≥ 15% при 10+ вызовах |
| `api_errors` | 3+ сбоя самого API модели |
| `token_hotspot` | участок съел ≥ 20% расхода и вдвое больше медианы |
| `spend_without_changes` | ≥ 15% расхода на участке, где не изменён ни один файл |
| `edit_revert` | поздняя правка вернула текст, который убрала прошлая |
| `file_churn` | один файл правился 4+ раз |
| `rewrite_loop` | файл перезаписан целиком 2+ раза |
| `human_corrections` | 2+ коротких реплики-разворота («нет», «не то», «стоп») |
| `interruptions` | 2+ прерывания агента человеком |
| `repeated_instruction` | человек повторил одно указание 2+ раза |
| `idle_gaps` | паузы дольше 10 минут |
| `slow_tool_calls` | 3+ вызова дольше минуты |
| `bash_instead_of_tool` | 5+ раз через Bash сделано то, для чего есть Read / Grep / Glob / Write / Edit |
| `missing_cli` | команда не найдена в системе 2+ раза («command not found») |
| `tool_permission_denied` | 2+ вызова отклонены по разрешениям |

Полный список типов — `FINDING_TYPES` в `detectors/__init__.py`: это единственный
источник правды. Тип, которого там нет, попадает в `meta.warnings`, а тест аудита
не даст выпустить его без проверки.

Пороги и формулы severity — в коде детекторов, каждый в своём файле. Severity
снижается, когда повтор может быть законным: между повторами правили файлы либо
сжимался контекст сессии (`compact_boundary` — агент мог забыть прошлый результат).
Вызовы сабагента (`isSidechain`) не складываются в одну серию с вызовами главного
потока: это разные исполнители.

## Правила, которые нельзя ломать

1. **Парсер не бросает исключений.** Любой вход: пустой файл, оборванная строка,
   неизвестный тип события, чужой формат. Проблемы уходят в `meta.warnings`.
2. **Каждая находка ссылается на существующие шаги.** `run_all` выбрасывает
   несуществующие `stepIds`, а находку без ссылок отбрасывает целиком.
3. **Упавший детектор не роняет отчёт** — его ошибка попадает в `meta.warnings`.
4. **«Значимых проблем не найдено» — нормальный результат.** Придумывать находки нельзя.
5. **Цену не выдумываем.** Неизвестная модель -> `cost: None` и `costPartial`.

## Проверка

```bash
python3 -m unittest discover -s tests -q          # 113 тестов
python3 -m analysis.cli ~/.claude/projects/<проект>/<uuid>.jsonl --top 10
```

| `tests/test_report.py` | покрытие шести направлений, полосы значимости, привязка рекомендаций к находкам, знаменатель доли ошибок |
| файл | что проверяет |
|---|---|
| `tests/test_parser.py` | порченые логи: пустой, оборванный, не-объекты в строках, неизвестные типы, отсутствующие поля, дедупликация usage |
| `tests/test_detectors.py` | каждый детектор по отдельности + прогон по всем настоящим логам на машине и по их обрезанным половинам |
| `tests/test_hard.py` | враждебные входы (BOM, CRLF, нулевые байты, эмодзи, перевёрнутое время, дубли tool_use_id, вложенность в 60 уровней, строка на 2 МБ), ложные срабатывания, фаззинг на 40 случайных логах, детерминизм, ранжирование, нагрузка |
| `tests/test_audit.py` | аудит: каждое утверждение находки перепроверяется по шагам независимо от детектора, на всех настоящих логах и на случайных |

Аудит — главный тест качества. Он ловит ровно то, за что снижают оценку: находку,
чьи ссылки на шаги не подтверждают заявленное. Проверяется и сам аудитор: тест
`test_auditor_catches_a_lie` подсовывает ему подделанную находку.

Что в логах на этой машине сработало хотя бы раз: все типы, кроме
`high_failure_rate` (нигде доля падений не дошла до 15%) — он закрыт только
юнит-тестами.
