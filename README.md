# cu-hack — разбор сессий кодинг-агента

Сервис принимает JSONL Claude Code, считает метрики, находит эпизоды для проверки и сохраняет отчёт с доказательствами. Объединены backend, детекторы и ML. Фронтенд ещё не реализован: в ветке `frontend` нет кода интерфейса. API можно проверить через Swagger.

## Запуск всего проекта

Из корня репозитория, с запущенным Docker Desktop:

```bash
docker compose up -d --build --wait
```

Открываем **http://localhost:8080/docs**. В `POST /api/sessions` загружаем один `.jsonl`. По умолчанию `llm_enabled=false`: анализ работает без ключа, на фактах и рекомендациях кода. Затем по полученному `analysis_id` запрашиваем статус и отчёт. Миграции PostgreSQL запускаются автоматически; данные сохраняются в Docker volumes.

Для ML задаём `OPENAI_API_KEY` и при необходимости `LLM_MODEL` в локальном корневом `.env`, пересоздаём backend командой `docker compose up -d backend` и при загрузке выбираем `llm_enabled=true`. Ключ в git не добавляем. Если ML запрошен, но ключа нет или ответ не прошёл проверку, получаем частичный отчёт с сохранёнными фактами.

Порты можно поменять через `API_PORT` и `DB_PORT` в `.env`. Остановка без удаления данных: `docker compose down`.

## Как соединены части

**Загрузка → один раз парсер → детекторы → адаптер → сжатие → ML при включении → проверка → БД и экспорты.**

- `src/api/` — загрузка, статусы, шаги, отчёт и скачивание файлов.
- `src/parsers/` — публичный интерфейс типизированных шагов и связывания вызовов; использует тот же основной парсер.
- `src/analysis/usage.py` — расход исходного агента: собирается при чтении файла, дедуплицируется по сессии и request/message ID, учитывает финальные обновления. Отсутствующие категории остаются неизвестными; неполные суммы помечены.
- `src/analysis/` — основной парсер и детекторы; покрывают шесть направлений кейса и проверку инструментов.
- `src/reports/builder.py` — переводит реальные шаги и находки в HTTP-контракт и ML-контракт. Все ссылки ведут к шагам загруженной сессии.
- `ml/agent_review/` — сжатие, промпт, вызов модели и проверка цитат. Фактический текст создаёт код; модель выбирает оценку и допустимый совет.
- `src/jobs/runner.py` — очередь в одном процессе, стадии анализа, обработка ошибок и отмены.
- `src/models/`, `src/crud/`, `src/alembic/` — PostgreSQL и миграции.
- `src/reports/exporters.py` — `report.json`, `report.md`, `CLAUDE.generated.md`.

HTTP-отчёт сохраняет версию 1; внутренний ML-пакет использует версию 2. Это разные контракты, адаптер связывает их. Сигналы полного детектора передаются в ML как `detector_observation`: сами по себе они не доказывают неэффективность. При недостатке доказательств модель может выбрать `uncertain`.

`ml/agent_review/prepare.py` и его небольшие детекторы остаются вспомогательным режимом для отдельной разработки ML. Сервер их не вызывает и второй раз лог не разбирает. Моковые данные и старый дублирующий контракт ответа модели удалены.

## Проверка

Сквозная проверка работающего API, без платных вызовов:

```bash
python3 scripts/check_api.py
```

Она загружает синтетическую сессию с повторами, проверяет отчёт, ссылки на шаги, пагинацию, экспорты, пустой файл, неизвестный формат и сохранение 3001 шага в PostgreSQL. Для дополнительного прогона самого большого файла из предоставленного архива:

```bash
python3 scripts/check_api.py --logs-zip "$HOME/Desktop/logs.zip"
```

Локальные тесты после установки зависимостей через `uv sync`:

```bash
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python -m unittest discover -s ml/tests -q
```

Тесты используют синтетические данные. Дополнительные проверки настоящих логов включаются при наличии `ml/data/logs.zip` либо через `TEST_LOGS_ZIP=/путь/к/logs.zip`. Личные папки Claude автоматически не читаются; архив в git и Docker-образ не входит.

## Ограничения

Это один экземпляр backend с последовательной фоновой обработкой; после перезапуска незавершённые задачи получают `interrupted`. Исходный файл ограничен 50 МиБ, строка — 5 МиБ. Парсер явно отмечает усечение и недостаток данных. Сжатие перед ML сохраняет тексты уже подготовленного эпизода; большие доказательства пропускаются явно. Точность оценок живой модели требует отдельной проверки с API-ключом.
