# cu-hack — разбор сессий кодинг-агента

Мы проектируем сайт по кейсу «Что наделал агент»: загружаем лог, находим проверяемые признаки неэффективной работы и получаем рекомендации для следующей сессии.

## Документы команды

1. [Что мы делаем и зачем — простыми словами](docs/01-problema-prostymi-slovami.md). Начинаем здесь: проблема, требования, пример, устройство сайта и ML без сложных терминов.
2. [Подробная архитектура и ML](docs/02-architecture-and-ml.md). Стек, парсер, метрики, модель, промпт, формат запросов и ответов, API, хранение, структура папок, проверки и этапы реализации.

3. [Бриф для дизайнера](docs/03-design-brief.md). Экраны и состояния интерфейса.

Документы написаны от лица команды. Полный сайт пока не создан. Визуальный дизайн разрабатывает наш дизайнер.

## ML-модуль

В [ml/README.md](ml/README.md) — простой работающий модуль анализа: промпт, входной контракт для backend, вызов модели, проверка ответа, локальная подготовка примеров из логов, тесты и Docker. Начните с режима `preview`: он не требует API-ключа и ничего не отправляет модели.

Основная цепочка: **лог → парсер → детектор и факты из кода → сжатие эпизода → модель выбирает оценку и цитаты → проверка → отчёт из фактов и допустимых советов**. Текущий контракт ML — `schema_version: "2"`; произвольное сочинение причин отключено.
